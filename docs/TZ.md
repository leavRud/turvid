# ТЗ: Turvid — сайт-дневник походов

Oct 19, 2026 · @Maksim

## 1. Цель и суть

Turvid — личный сайт-дневник походов. После похода загружаешь записанный трек и фото, привязываешь фото и заметки к местам на маршруте, а потом «проходишь» поход заново, двигая стрелку по карте туда и обратно.

- **Для кого:** один пользователь (я). Другим — только просмотр по ссылке.
- **Где:** компьютер и телефон, включая загрузку трека и фото с телефона.
- **Главная фишка:** стрелка на маршруте, которая примагничивается к точкам с фото и заметками.

**Термины**

| Термин | Что значит |
| --- | --- |
| Поход | Один загруженный трек со всем, что к нему привязано. Может длиться несколько дней |
| Трек | Линия маршрута: точки с координатами, а если есть — с временем и высотой |
| Позиция | Расстояние от старта вдоль трека в метрах. Всё на маршруте адресуется позицией |
| Точка | Место на треке с названием, описанием, фото и видео |
| Остановка | Место, где долго стоял. Находится автоматически по времени, не хранится |
| День | Кусок трека между ночными разрывами во времени |

**Не входит в первую версию:** запись трека в реальном времени (позже отдельное мобильное приложение), планирование маршрутов, соцсеть и комментарии, офлайн-режим, коррекция высоты по карте высот (этап после MVP).

## 2. Стек и архитектура

Вся обработка трека и фото идёт в браузере, Supabase только хранит данные и отдаёт их. Своего сервера нет, сайт — статика.

&#91;embedded content: архитектура · браузер, Supabase, хостинг\]

| Задача | Решение |
| --- | --- |
| Сборка и язык | Vite + TypeScript (strict), без UI-фреймворка, ES-модули |
| Карта | MapLibre GL JS; подложка — OpenFreeMap (бесплатные векторные тайлы без ключа) |
| Разбор файлов | @tmcw/togeojson (GPX, KML), JSZip (распаковка KMZ), GeoJSON — нативно |
| Геометрия | @turf/turf: длина, точка на расстоянии, ближайшая точка на линии; упрощение — алгоритм Дугласа–Пекера (simplify-js) |
| Тяжёлые вычисления | Web Worker, чтобы интерфейс не зависал на файле в 50 000 точек |
| Фото | exifr — чтение EXIF; сжатие через canvas (или browser-image-compression); heic2any — фото с iPhone; mp4box.js — метаданные видео; tz-lookup — часовой пояс по координатам |
| Графики | Свой SVG (профиль высоты, шкала времени, статистика) |
| Бэкенд | Supabase: Auth (вход по ссылке на почту), Postgres с RLS, Storage, одна Edge Function для публичных ссылок |
| Хостинг | Vercel или Netlify, автодеплой из GitHub |

**Структура кода** (папки в `src/`): `parse/` — разбор форматов, `track/` — обработка трека (воркер), `map/` — карта, стрелка, слои, `player/` — ползунок, магнит, нижняя полоса, `photos/` — EXIF, сжатие, раскладка, `api/` — всё общение с Supabase, `pages/` — экраны, `ui/` — общие компоненты. Логика обработки трека — чистые функции без DOM, покрыть тестами на Vitest.

## 3. Модель данных (Supabase)

Три таблицы: поход, точка, медиа (фото и видео). Упрощённый трек лежит прямо в строке похода как JSON (2–5 тыс. точек — это 100–300 КБ), исходный файл — в Storage. Остановки и дни не хранятся, а считаются на клиенте из трека.

```sql
create table hikes (
  id            uuid primary key default gen_random_uuid(),
  user_id       uuid not null references auth.users on delete cascade,
  title         text not null,
  started_at    timestamptz,          -- null, если в треке нет времени
  finished_at   timestamptz,
  timezone      text not null,        -- IANA-зона по координатам старта, например 'Europe/Moscow'
  distance_m    integer not null,
  moving_s      integer,              -- время в движении
  elev_gain_m   integer,              -- null, если высота ненадёжна
  elev_range_m  integer,
  track         jsonb not null,       -- упрощённый трек, формат ниже
  bbox          double precision[4] not null, -- [minLon, minLat, maxLon, maxLat]
  source_path   text,                 -- исходный файл в Storage
  share_token   text unique,          -- null = ссылка выключена
  created_at    timestamptz not null default now()
);

create table points (
  id          uuid primary key default gen_random_uuid(),
  hike_id     uuid not null references hikes on delete cascade,
  pos_m       double precision not null, -- позиция вдоль трека
  lat         double precision not null,
  lon         double precision not null,
  title       text not null default '',
  description text not null default '',
  created_at  timestamptz not null default now()
);

create table media (
  id          uuid primary key default gen_random_uuid(),
  hike_id     uuid not null references hikes on delete cascade,
  point_id    uuid references points on delete set null, -- null = неразобранное
  kind        text not null check (kind in ('photo', 'video')),
  path        text not null,   -- сжатое фото или видео как есть, в Storage
  thumb_path  text not null,   -- превью 400 px (у видео — кадр)
  duration_s  real,            -- только для видео
  taken_at    timestamptz,
  lat         double precision,
  lon         double precision,
  width       integer not null,
  height      integer not null,
  sort        integer not null default 0
);
```

**Формат `track`** — колонки вместо массива объектов, чтобы JSON был компактным: `{ "lon": [...], "lat": [...], "ele": [...] | null, "t": [...] | null, "dist": [...] }`. `t` — секунды от `started_at`, `dist` — накопленное расстояние в метрах. Все массивы одной длины.

**Доступ**

- RLS на всех трёх таблицах: читать и менять строки может только владелец (`user_id = auth.uid()`, для `points` и `media` — через их поход).
- Bucket `media приватный, путь <user_id>/<hike_id>/<uuid>.<расширение>`. Владелец получает фото через подписанные ссылки.
- Публичная ссылка: Edge Function `share` принимает `share_token`, проверяет его и возвращает поход, точки и фото с подписанными ссылками на 1 час. Без токена — 404.
- После своей регистрации отключить регистрацию новых пользователей в настройках Auth.

## 4. Импорт и обработка трека

Файл обрабатывается в Web Worker за один проход и превращается в упрощённый трек со статистикой. Эталонный файл для проверки — экспорт Zepp с Amazfit T-Rex 3 Pro: 51 000 точек раз в секунду, 13,7 МБ, два дня с ночным разрывом, около 32 км.

**Форматы:** GPX (обязательно), KML, KMZ, GeoJSON (`LineString`, `MultiLineString`, `Feature` и `FeatureCollection` с ними). Несколько треков и сегментов в файле склеиваются по времени. Метки `<wpt>` из GPX предлагаются как готовые точки.

**Шаги обработки**

1. **Разбор** в общий вид: массив `{lat, lon, ele?, t?}`. Если хоть у одной точки нет времени — режим «без времени»: шкала времени, остановки и раскладка фото по времени отключаются.
2. **Чистка:** выкинуть точки-дубликаты и выбросы — скачок со скоростью больше 50 км/ч.
3. **Дни:** разрыв во времени больше 3 часов начинает новый день. Разрыв не рисуется как перелёт: на карте и шкале это граница дней.
4. **Расстояние:** считать по формуле гаверсинуса, но не между всеми точками подряд, а между точками, отстоящими друг от друга не меньше чем на 5 м. Иначе GPS-дрожание на стоянках накручивает лишние километры: в эталонном файле «сырые» 32,7 км против 31,8 км после прореживания.
5. **Высота:** сгладить скользящей медианой по 15 точкам. Набор высоты считать с порогом 5 м: подъём засчитывается, только когда высота выросла на 5 м от последнего минимума. Высота помечается ненадёжной, если упала ниже −50 м или конец ушёл от начала больше чем на 50 м при близких координатах. В эталонном файле так и есть: барометр уплыл за ночь с 10 до −117 м. Ненадёжная высота не показывается, набор не считается.
6. **Остановки:** 5 минут и дольше в круге радиусом 30 м. В эталонном файле таких 23, самые длинные — 98, 89 и 50 минут.
7. **Упрощение:** Дуглас–Пекер с допуском 3 м, потолок — 5 000 точек (при превышении допуск растёт). Время, высота и расстояние сохраняются у оставшихся точек.
8. **Статистика:** расстояние, общее время, время в движении (без остановок), средняя скорость в движении, число дней, набор и перепад высот (если высота надёжна).

**Часовой пояс похода** определяется по координатам первой точки трека (tz-lookup, работает без сети) и сохраняется в `hikes.timezone`. Все времена на экране показываются в этом поясе.

**Ошибки, которые показываются человеку:** «в файле нет трека», «формат не поддерживается», «файл больше 50 МБ», «трек короче 100 м». Предупреждения не останавливают импорт: «нет времени — часть функций отключена», «высота ненадёжна».

**Готово, когда:** эталонный файл открывается за 5 секунд на ноутбуке и за 15 на телефоне, показывает 2 дня и 31–33 км, высота помечена ненадёжной, интерфейс не замирает во время обработки.

## 5. Экран просмотра похода

Всё состояние экрана — одна позиция на треке в метрах. Карта, стрелка, карточка точки и нижняя полоса только отображают её, а ползунок, перетаскивание стрелки и кнопки её меняют. Визуальный ориентир — [макет главного экрана](https://claude.ai/artifact/AsKdrp7GFGKeFuEGEAq74J).

**Раскладка на компьютере:** сверху название, даты и сводка (расстояние, время, набор высоты, точки и фото). Ниже карта слева и панель точки справа. Под картой — нижняя полоса с ползунком.

**Стрелка**

- Стоит на треке в точке текущей позиции (интерполяция между соседними точками).
- Повёрнута по направлению движения. Направление брать между точками примерно в 20 м до и после позиции, иначе стрелка дёргается на мелких зигзагах.
- Пройденная часть трека — цветом акцента, остальная — приглушённая.
- Плашка у стрелки: километр от старта, день, время суток, высота (если надёжна).
- **Перетаскивание мышью или пальцем:** позиция = ближайшая точка трека к курсору. Искать только в окне ±1 км от текущей позиции, иначе на маршруте «туда-обратно» стрелка прыгнет на встречную ветку. Если курсор дальше 50 м от трека, стрелка стоит.
- Режим «следовать»: карта плавно держит стрелку в кадре. Включён по умолчанию, выключается, если пользователь сам сдвинул карту.

**Ползунок и магнит**

- Ползунок от 0 до длины трека в метрах.
- **Магнит:** если позиция ближе 12 пикселей ползунка (или 12 пикселей экрана при перетаскивании стрелки) к точке с фото или заметкой, она приклеивается к точке. Тянешь дальше — отрывается и едет дальше. На точке открывается её карточка.
- Кнопки «к предыдущей» и «к следующей» точке.
- Клавиатура: ← → на 50 м, с Shift на 500 м, PageUp и PageDown — к точкам, Home и End — старт и финиш.
- Позиция пишется в адрес страницы (`?pos=12340`), чтобы ссылка открывала то же место.
- Кнопка «проиграть»: стрелка едет сама, скорость ×1, ×2, ×4 от условного «1 км за 2 секунды», с паузой 2 секунды на каждой точке.

**Нижняя полоса** — три режима, выбирается автоматически, есть ручной переключатель:

| Режим | Когда включается | Что показывает |
| --- | --- | --- |
| Профиль высоты | Высота надёжна и перепад больше 150 м | График высоты по расстоянию, метки точек, линия текущей позиции |
| Шкала времени | Во всех остальных случаях, если в треке есть время | Дни подряд с подписями, ночь как разрыв, остановки отметками (длина ≥ 10 минут — подпись с длительностью), скорость полосой цвета, метки точек |
| Только ползунок | Нет ни времени, ни надёжной высоты | Шкала километров и метки точек |

**Панель точки** (справа на компьютере, выезжающая снизу шторка на телефоне): главное фото, лента превью, название, описание, километр, время и высота. Между точками — текущий километр, высота, время и кнопка «Поставить точку здесь». Внизу панели — список всех точек похода, клик переносит стрелку.

## 6. Точки и фото

Фото раскладываются по маршруту сами, а человек только проверяет и правит раскладку перед сохранением.

**Точка**

- Создаётся кнопкой «Поставить точку здесь» на текущей позиции или долгим нажатием на карту (притягивается к ближайшему месту трека).
- Поля: название до 80 символов, описание до 5 000 символов (простой текст, переносы строк сохраняются), фото в нужном порядке.
- Точку можно передвинуть по треку, перетащив её маркер, и удалить. При удалении её фото становятся неразобранными.

**Загрузка фото**

- Выбор нескольких файлов сразу: перетаскиванием на компьютере, из галереи на телефоне. JPEG, PNG, WebP и HEIC (фото с iPhone, конвертируются в браузере) до 25 МБ каждое.
- EXIF читается из исходника до сжатия: время съёмки, часовой пояс (`OffsetTimeOriginal`, если есть), координаты, ориентация.
- Сжатие: длинная сторона 2048 px, WebP качества 0,82, плюс превью 400 px. Сжатые копии без EXIF. Оригиналы не хранятся.
- Загрузка параллельно по 3 файла, с прогрессом и повтором при обрыве связи.

**Фото без данных о съёмке** — частый случай для фото от друзей: Телеграм при обычной отправке вырезает время и координаты, а при отправке файлом и через облачные диски они сохраняются.

- Если в EXIF нет ни времени съёмки, ни координат, время берётся из имени файла по известным шаблонам: `photo_2026-10-17_14-32-05` (Telegram Desktop, это время отправки), `IMG_20261017_143205` (камеры Android). Такое фото раскладывается с пометкой «время примерное».
- Если и имя не помогает — в неразобранные.
- При загрузке таких фото показывается подсказка: «Похоже, фото сжаты мессенджером. Попроси прислать их файлом — тогда они сами встанут на маршрут».

**Видео**

- MP4, MOV и WebM до 50 МБ — это лимит на один файл в бесплатном Supabase (проверить перед этапом 4). Видео не пережимается, файл больше лимита не загружается с понятным сообщением. Сжатие в браузере — после MVP. Видео с iPhone (MOV с кодеком HEVC) Chrome проигрывает не на всех устройствах: сайт проверяет это через `canPlayType` и предупреждает при загрузке, перекодирование — после MVP.
- Длительность и превью-кадр (на первой секунде, 400 px) достаются в браузере через `<video>` и canvas.
- Время съёмки — из метаданных MP4 (`creation_time`, через mp4box.js), координаты — если телефон их записал. Раскладываются тем же алгоритмом, что и фото.
- В панели точки видео стоят в той же ленте, что и фото, со значком и длительностью; открываются во встроенном плеере на весь экран.
- Видео быстро съедают место в бесплатном Storage, поэтому на экране похода видно, сколько места занято.

**Автораскладка** — для каждого фото по очереди:

1. Есть координаты → ближайшее место на треке. Если до трека больше 200 м, фото помечается «далеко от маршрута», но всё равно ставится в ближайшее место.
2. Нет координат, но есть время и в треке есть время → позиция, где ты был в этот момент. Время без часового пояса считается во временной зоне похода (`hikes.timezone`). Если момент вне похода больше чем на 30 минут — в неразобранные.
3. Ни того ни другого → в неразобранные.
4. Фото, разложенные в пределах 150 м по треку друг от друга, собираются в одну новую точку. Если рядом, ближе 100 м, уже есть точка — фото добавляются в неё.

**Экран проверки** перед сохранением: карта с предложенными точками и список «точка → её фото». Можно перетащить фото в другую точку или в неразобранные, переименовать точки, отменить всё. Неразобранные фото потом лежат в отдельном лотке на экране похода, откуда их можно бросить на трек.

**Просмотр фото:** на весь экран, листание свайпом и стрелками, подпись — название точки и время съёмки.

## 7. Остальные экраны

| Экран | Что на нём |
| --- | --- |
| Вход | Поле почты и кнопка «Прислать ссылку». Без паролей |
| Мои походы | Карточки от новых к старым: мини-карта трека (SVG из упрощённого трека, без тайлов), название, даты, км, дни, число фото. Кнопка «Новый поход» |
| Новый поход | Перетащить или выбрать файл → прогресс обработки → превью: карта, дни, статистика, предупреждения → название (по умолчанию дата похода) → «Сохранить» → сразу предложение загрузить фото |
| Просмотр похода | Раздел 5. Плюс меню: переименовать, поделиться, скачать исходный файл, удалить (с подтверждением вводом названия) |
| Статистика | Итоги за всё время: походы, км, дни, ночёвки, фото. Столбцы км по месяцам с переключателем года. Рекорды: самый длинный поход, самый длинный день, самый большой перепад высот. Карта всех маршрутов разом, клик по треку открывает поход |
| Публичный просмотр | `/s/<token>`: тот же экран просмотра без кнопок правки, меню и лотка неразобранных фото. В заголовке страницы и превью ссылки — название похода |

**Поделиться:** переключатель в меню похода создаёт случайный `share_token` (не меньше 22 символов) и показывает ссылку с кнопкой «Скопировать». Выключение стирает токен, старая ссылка перестаёт работать. Повторное включение даёт новую ссылку.

**Тёмная тема:** по умолчанию как в системе, плюс переключатель «светлая / тёмная / как в системе», выбор запоминается. Все цвета — CSS-переменные; у карты свой тёмный стиль.

**Телефон:** все экраны работают от ширины 360 px. На экране похода карта во всю ширину, ползунок прижат к низу, панель точки — шторка, которая вытягивается вверх. Кнопки и ползунок не меньше 44 px. Загрузка трека и фото с телефона — обязательный сценарий, а не запасной.

## 8. Этапы и критерии готовности

Каждый этап — законченный кусок, который можно потрогать. Для вайбкодинга удобно отдавать нейросети по одному этапу: этот документ целиком как контекст плюс «делаем этап N».

1. **Каркас.** Vite + TS, проект Supabase, вход по почте, деплой на хостинг.
   - Готово: открываю сайт с телефона, вхожу по ссылке из письма, вижу пустой список походов.
2. **Импорт и список.** Разбор форматов в воркере, обработка (раздел 4), сохранение, список походов, удаление.
   - Готово: эталонный файл Zepp импортируется по критериям раздела 4; поход появляется в списке с мини-картой.
3. **Просмотр.** Карта, трек, стрелка, ползунок, перетаскивание стрелки, нижняя полоса, клавиатура, позиция в адресе.
   - Готово: на эталонном треке стрелка проходит оба дня без рывков, полоса в режиме шкалы времени с 2 днями и остановками.
4. **Точки и фото вручную.** Создание и правка точек, загрузка фото и видео, магнит, панель точки, полноэкранный просмотр.
   - Готово: 20 фото с телефона загружаются меньше чем за минуту по Wi-Fi, ползунок прилипает к каждой точке.
5. **Автораскладка.** EXIF, алгоритм из раздела 6, экран проверки, лоток неразобранных.
   - Готово: фото из эталонного похода сами встают на маршрут, ручная правка нужна не больше чем для каждого десятого.
6. **Поделиться, статистика, тёмная тема.**
   - Готово: ссылка открывается в режиме инкогнито без входа, после выключения отдаёт 404; тема переключается без перезагрузки.
7. **Полировка телефона.** Шторка, жесты, проверка всех экранов на ширине 360 px.

**После MVP:** коррекция высоты по карте высот (DEM), проигрывание с фото в режиме слайд-шоу, мобильное приложение с записью трека, офлайн-просмотр.
